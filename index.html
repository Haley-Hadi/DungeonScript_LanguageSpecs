DungeonScript Specification

DungeonScript is a domain-specific language (DSL) tailored for TTRPG Game Masters. It allows you to define complex NPCs, locations, and encounters using a readable, structured syntax that compiles into usable formats for VTTs and note-taking apps.

Core Entity Types

DungeonScript operates on three primary entity declarations:

  • NPC: The central unit for characters, containing stats, saving throws, and actions.
  • Location: A container for world-building, capable of nesting NPCs and Encounters.
  • Encounter: A tactical block used to define combat or social challenges.

Stats & Modifiers

Modifiers are the backbone of TTRPG mechanics. DungeonScript automates this calculation using the standard formula:

Modifier = floor((BaseStat - 10) / 2)

When an NPC is defined with a stat like STR: 18, the compiler internally calculates a +4 modifier. These can be dynamically referenced in Action damage strings using keywords like STR, DEX, or PROF.

Language Grammar

The syntax is strictly enforced by an Ohm.js grammar to ensure data consistency across your campaign files.

NPC = "NPC" string "{" NPCBody "}"
Location = "Location" string "{" LocationBody "}"
Property = identifier ":" (number | string)
StatBlock = "stats" "{" Stat* "}"
Action = "Action" string "{" ActionBody "}"

Compiler Safety & Validation

The compiler includes built-in semantic checks to catch common preparation errors before they reach your game table:

  • HP Validation: Ensures all NPCs have a health pool greater than 0.
  • Null Safety: Missing stats default to 10 (+0) to ensure compatibility with VTT importers.
  • Reference Checks: Ensures that damage strings only reference valid stat abbreviations.

Complete Example

A full .ds file demonstrating how entities relate to one another:

NPC "Goblin" {
  stats { DEX: 14, HP: 7, AC: 13 }
  Action "Nimble Escape" { type: "utility" }
}

Location "Cragmaw Hideout" {
  environment: "Cave"
  "Goblin" 
}
