DungeonScript Specification

DungeonScript is a domain-specific language (DSL) tailored for TTRPG Game Masters. It allows you to define complex NPCs, locations, and encounters using a readable, structured syntax that compiles into usable formats for VTTs and note-taking apps.

This document defines the DungeonScript language.

NPC "Goblin" {
  stats {
    STR: 8
    DEX: 14
    CON: 10
    INT: 10
    WIS: 8
    CHA: 8
    HP: 7
    AC: 15
    proficiency: 2
  }
  saving_throws {
    STR: -1
    DEX: 2
  }
  action "Scimitar" {
    type: "melee"
    damage: "1d6 + STR + PROF"
  }
}

Location "Cragmaw Hideout" {
  safety: 8
  environment: "Cave"
  NPC "Guard" {
    stats {
      HP: 20
    }
  }
  Encounter "Ambush" {
    difficulty: "medium"
  }
}

print("The party hears distant footsteps.");

Language Overview

A DungeonScript program consists of one or more declarations. Declarations define entities such as NPCs, Locations, and Encounters. The language supports nesting of entities within Locations and Encounters, custom properties, stat blocks with automatic modifier calculation, and a simple print statement for narrative elements.

The language is statically validated by an Ohm.js grammar, ensuring consistency and preventing common errors in TTRPG preparation.

Entity Types

DungeonScript operates on three primary entity declarations:

  • NPC: Represents characters or creatures, containing stats, saving throws, actions, and custom properties.
  • Location: A container for world-building, capable of nesting NPCs and Encounters with environmental properties.
  • Encounter: Defines tactical or social challenges, which can contain nested entities and properties.

Entities can be nested: NPCs and Encounters can appear inside Locations or other Encounters, allowing hierarchical world-building.

Properties & Values

Entities can have custom properties defined as key-value pairs. Property keys are identifiers, and values can be numbers, strings (in quotes), or identifiers.

property = identifier ":" value
value = number | string | identifier

Examples:

difficulty: "medium"
safety: 8
environment: "Cave"

Stats & Modifiers

NPCs can have stat blocks and saving throw blocks. Stats are defined as ability scores (STR, DEX, CON, INT, WIS, CHA) and other attributes like HP, AC, proficiency.

Modifiers are automatically calculated using the standard TTRPG formula:

Modifier = floor((BaseStat - 10) / 2)

For example, STR: 14 gives a +2 modifier. These modifiers can be referenced in action damage strings using the ability abbreviation (STR, DEX, etc.) or PROF for proficiency.

Saving throws are defined similarly, with explicit modifier values.

stats {
  STR: 14
  DEX: 16
  HP: 20
  AC: 15
  proficiency: 2
}
saving_throws {
  STR: 2
  DEX: 3
}

Actions

NPCs can define actions, which are abilities or attacks with custom properties. Actions support damage strings that can reference stat modifiers.

action "Scimitar" {
  type: "melee"
  damage: "1d6 + STR + PROF"
  description: "Slashing"
}

The damage string can include dice notation and modifier references like STR, DEX, CON, INT, WIS, CHA, PROF.

Nesting

Entities can be nested to create hierarchical structures. NPCs and Encounters can be placed inside Locations or other Encounters.

Location "Castle" {
  safety: 8
  NPC "Guard" {
    stats { HP: 20 }
  }
  Encounter "Ambush" {
    difficulty: "medium"
    NPC "Archer" {
      stats { DEX: 16 }
    }
  }
}

This allows building complex worlds with entities contained within locations.

Print Statement

The print statement allows adding narrative text or debug output to the program.

print("The party hears distant footsteps.");

It takes a string argument and outputs it during compilation or execution.

Compiler Features

The DungeonScript compiler provides several features for robust TTRPG preparation:

  • Validation: Syntax checking and semantic validation ensure correct structure.
  • Null Safety: Missing stats default to 10 (+0) for compatibility.
  • Modifier Calculation: Automatic calculation of ability modifiers from base stats.
  • Optimization: Merging duplicate properties and normalizing declarations.
  • Output Generation: Compiles to Markdown suitable for notes and VTT import.
  • JSON Conversion: Helper to convert JSON monster data to DungeonScript source.

The compiler pipeline includes parsing, analysis, optimization, and generation stages.

Grammar

The DungeonScript syntax is defined by the following Ohm.js grammar:

dungeonscript {
    Program     = Declaration+
    Declaration = NPC | Location | Encounter | PrintStmt | space

    PrintStmt   = "print" "(" str ")" ";"

    Encounter = "Encounter" (str | identifier) "{" EncounterBody "}"
    EncounterBody = (Item | space)*
    
    Item        = property | Encounter | NPC

    Location  = "Location" (str | identifier) "{" LocationBody "}"
    LocationBody = (property | Item | space)*

    NPC       = "NPC" (str | identifier) "{" NPCBody "}"
    NPCBody     = (StatBlock | SavingThrowBlock | Action | property | space)*

    StatBlock   = "stats" Stats
    SavingThrowBlock = "saving_throws" Stats
    
    Stats       = "{" Stat* "}"
    Stat        = identifier ":" number

    Action    = "action" (str | identifier) "{" ActionBody "}"
    ActionBody  = (property | space)*

    identifier  = ~keyword alnum+
    number      = digit+
    property    = identifier ":" space* value
    value       = number | str | identifier
    
    keyword     = "NPC" | "Location" | "Encounter" | "stats" | "saving_throws" | "action" | "print"
    str         = "\"" (~"\"" any)* "\""
}

Markdown Output

The compiler can generate Markdown output from DungeonScript source, suitable for notes and VTT import. This conversion is performed by the generator pipeline.

Example: Input DungeonScript

NPC "Goblin Warrior" {
  stats {
    STR: 15
    DEX: 14
    CON: 12
    INT: 10
    WIS: 11
    CHA: 10
    HP: 22
    AC: 15
    proficiency: 2
  }
  action "Scimitar" {
    type: "melee"
    damage: "1d6 + STR + PROF"
  }
}

Example: Generated Markdown Output

---
type: npc
name: Goblin Warrior
HP: 22
AC: 15
---

# Goblin Warrior

**Proficiency Bonus:** +2

## Stats
| Stat | Value | Modifier |
| :--- | :--- | :--- |
| STR | 15 | +2 |
| DEX | 14 | +2 |
| CON | 12 | +1 |
| INT | 10 | +0 |
| WIS | 11 | +0 |
| CHA | 10 | +0 |

## Actions and Attacks

### Scimitar
- **Type**: melee
- **Damage/Effect**: 1d6 +2 +2

Key features of the Markdown output:

  • YAML Frontmatter: Metadata for VTT systems and tracking
  • Automatic Modifier Calculation: Ability scores are converted to modifiers using the formula: floor((score - 10) / 2)
  • Damage String Resolution: Tokens like STR, DEX, PROF are replaced with calculated modifiers
  • Stat Tables: Organized presentation of all ability scores and modifiers

JSON to DungeonScript Conversion

The ds-generator.js module converts standard JSON monster data (like from D&D 5e sources) into DungeonScript AST and source code.

Example: Input JSON Monster

{
  "name": "Goblin",
  "str": 8,
  "dex": 14,
  "con": 10,
  "int": 10,
  "wis": 8,
  "cha": 8,
  "hp": { "average": 7 },
  "ac": [15],
  "cr": 0.25,
  "action": [
    {
      "name": "Scimitar",
      "entries": ["Melee Weapon Attack: +4 to hit, reach 5 ft., 1d6+2 damage"]
    }
  ]
}

Example: Generated DungeonScript

NPC "Goblin" {
  stats {
    STR: 8
    DEX: 14
    CON: 10
    INT: 10
    WIS: 8
    CHA: 8
  }
  HP: 7
  AC: 15
  CR: 0.25
  action "Scimitar" {
    description: "Melee Weapon Attack: +4 to hit, reach 5 ft., 1d6+2 damage"
  }
}

Conversion Process

The conversion handles:

  • Ability Scores: Maps STR, DEX, CON, INT, WIS, CHA from JSON to DungeonScript stats block
  • Hit Points: Extracts average HP value from JSON structure
  • Armor Class: Converts array or single AC value
  • Challenge Rating: Preserves CR for encounter building
  • Actions & Traits: Converts actions array to DungeonScript action blocks
  • Additional Properties: Preserves speed, languages, and other attributes

Usage

The conversion can be invoked programmatically:

import { convertMonsterToAST } from "./src/ds-generator.js"

const jsonMonster = { /* ... */ }
const ast = convertMonsterToAST(jsonMonster)

// Or use the compiler pipeline:
import compile from "./src/compiler.js"
const source = compile(jsonSource, "js") // Convert to Markdown

CLI Command

To convert a JSON monster file to DungeonScript using the command line:

npm run generate-ds path/to/monster.json

This will output the generated DungeonScript source to stdout.

CLI Commands

DungeonScript provides the following command-line tools:

JSON to DungeonScript Conversion

npm run generate-ds <path-to-json-file>

Converts a JSON monster file to DungeonScript source code and outputs to stdout.

Example:

npm run generate-ds ./examples/goblin.json

DungeonScript to Markdown Conversion

Currently, DungeonScript-to-Markdown conversion is available through the programmatic API:

import compile from "./src/compiler.js"

const dungeonScriptSource = `NPC "Goblin" { ... }`
const markdown = compile(dungeonScriptSource, "js")
console.log(markdown)

Compiler Pipeline Modes

The compiler supports multiple output modes via the programmatic API:

  • "parsed" — Validates syntax and returns "Syntax is ok"
  • "analyzed" — Returns semantic AST with Program, NPC, Location, and Encounter objects
  • "optimized" — Returns normalized AST after merging duplicates
  • "js" — Generates Markdown output from the optimized AST

Example usage:

import compile from "./src/compiler.js"

const source = `NPC "Goblin" { stats { STR: 14 } }`

const syntax = compile(source, "parsed")           // "Syntax is ok"
const analyzed = compile(source, "analyzed")       // AST
const optimized = compile(source, "optimized")     // Normalized AST
const markdown = compile(source, "js")             // Markdown output
